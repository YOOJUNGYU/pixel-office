PIXEL OFFICE · v1.0.74

Pixel Office 기술 구조

LAN 안의 모든 PC에서 돌아가는 코딩 에이전트(Claude Code, Codex)를 브라우저 속 픽셀 아트 사무실의 캐릭터로 보여주는 앱. 각 PC에 Node 서버가 하나씩 떠 있고, 브라우저 SPA는 그 서버에만 붙는다. 서버끼리는 UDP로 직접 통신하고, 인터넷 너머 "누가 접속 중인지"만 Cloudflare 릴레이가 중계한다.

33,369webview-ui/src 줄 (TS/TSX)
10,838server/src 줄
3,634core/src 줄 (생성 파일 제외)
770relay/src 줄
104테스트 파일 (Vitest)
4서버 런타임 의존성 (Fastify 계열만)

00한 줄 요약

FRONTEND

React 19 + TypeScript + Canvas 2D

Vite 8로 빌드하는 SPA. UI 패널은 React, 사무실 화면은 게임 라이브러리 없이 직접 만든 Canvas 엔진. Tailwind 4 + CSS 변수, 자체 i18n(ko/en), PWA.

BACKEND

Node 22 + TypeScript + Fastify 5

esbuild로 dist/cli.js 한 파일에 묶는 CLI 서버. HTTP·WebSocket은 Fastify, P2P는 Node 표준 dgram UDP, 암호는 node:crypto. 그 외 런타임 의존성 없음.

RELAY

Cloudflare Worker + Durable Object

무료 플랜 안에서 돌아가는 WebSocket 허브 하나. 공개 오피스의 접속자 목록과 아케이드 점수 심판만 맡는다.

CORE

공유 TypeScript 패키지

AsyncAPI 3.0 스펙에서 생성한 메시지 타입, 프로토콜 상수, 게임 로직(고정 틱·정수 연산). 아무것에도 의존하지 않는다.

01전체 구조

PC 한 대 기준. 브라우저는 자기 PC의 서버(127.0.0.1:47801)에만 접속하고, 다른 PC와는 서버가 대신 이야기한다.

02모노레포 레이어링

npm workspaces 모노레포. core/는 아무것에도 의존하지 않고, 나머지 셋은 core/에만 의존한다. 서버와 웹뷰가 서로 import하지 않으니 둘 사이의 계약은 프로토콜 하나뿐이다.

패키지역할런타임빌드

03프론트엔드

언어는 TypeScript 5.9 (target ES2022, jsx: react-jsx). 핵심 설계는 React와 게임 상태의 분리다. 사무실 안의 캐릭터·가구·이펙트는 React state가 아니라 명령형 객체 OfficeState에 있고, Canvas 렌더러가 그것을 그린다. React는 버튼, 패널, 모달, 말풍선 오버레이 같은 DOM 크롬만 맡는다.

04백엔드 (로컬 서버)

언어는 TypeScript (Node16 모듈, ES2022). 각 PC에 설치되는 데몬형 CLI다. 클라우드 서버가 아니라 사용자 PC 위의 로컬 서버라는 점이 중요하다. 브라우저 UI는 루프백에서만 받고, 다른 PC와의 통신은 UDP P2P로 한다. DB 없이 ~/.pixel-office/의 JSON 파일(원자적 tmp+rename 저장)을 쓴다.

영역기술메모
런타임Node.js 22.23.3공식 바이너리를 설치 파일에 동봉 (SHA-256 검증). 사용자가 Node를 깔 필요 없음
웹 서버Fastify 5 + @fastify/websocket, @fastify/static, @fastify/cors유일한 런타임 의존성 4개. /ws, /ws/transcript, /api/health|ping|quit, SPA 정적 파일
번들esbuild 0.28Fastify까지 전부 dist/cli.js 하나로. 실행에 node_modules 불필요. 버전은 빌드 시 __APP_VERSION__로 주입
P2P 네트워크dgram (UDP 47800)평문 hello + 쌍별 암호 presence / 팀 브로드캐스트. 데이터그램 ≤ 1200B, 넘치면 deflate 후 최대 48조각 분할
암호node:cryptoX25519 신원키, HKDF로 쌍·팀 키 유도, AES-256-GCM 봉인, TOFU 키 고정, 채널별 재전송 방지 seq
압축zlib큰 presence, 공유 레이아웃, 업데이트 tgz 해제
릴레이 클라이언트Node 22 전역 WebSocket새 의존성 없이 WSS. 백오프, 하프오픈 감지, OS 인증서 저장소를 신뢰 CA에 추가(사내 TLS 검사 대응)
프로세스child_process트레이 헬퍼, WSL 프로세스 확인(wsl.exe), 업데이트 재시작, PWA 창 열기
테스트Vitest 4 + wsCLI·자동업데이트 e2e 포함 (가짜 GitHub API)

05프로토콜: 스펙이 먼저

브라우저 ⇄ 서버 메시지는 AsyncAPI 3.0 문서 core/asyncapi.yaml이 유일한 원본이다. npm run asyncapi:generate(@asyncapi/modelina)가 core/src/messages.ts를 생성하고, CI가 생성물과 스펙이 어긋나면 실패시킨다. 모든 메시지는 additionalProperties: false.

webviewReady ─▶ officeAccess {readOnly, version}
              ◀─ 에셋(캐릭터·펫·바닥·벽·카펫·가구)
              ◀─ settingsLoaded → profileLoaded → officesState
              ◀─ layoutLoaded → officeSnapshot → peopleDirectory
              ◀─ autostartState → relayState → updateAvailable
이후 1초마다  ◀─ officeSnapshot {agents, people, selfPeerId} + peopleDirectory

06릴레이 (Cloudflare)

구성

  • Worker 1개 + Durable Object hub 정확히 1개 (SQLite 기반, 무료 플랜)
  • WebSocket Hibernation: ping/pong은 setWebSocketAutoResponse로 DO를 깨우지 않음
  • hub.ts는 순수 결정 함수, index.ts는 얇은 껍데기 → 테스트가 쉬움

무엇을 나르나

  • 1.0.64부터 "누가 접속 중인지"만 (me → roster/person/join/leave)
  • 에이전트·채팅·아바타·레이아웃은 LAN(UDP)에만
  • 아케이드: 시드 티켓 HMAC 발급 → 입력 기록을 릴레이가 직접 재생해 점수 검증

비용 방어

  • DO는 수신 메시지만 과금 → 하루 예산 1,900,000 (무료 2M의 95%)
  • 소켓당 분당 120 프레임 넘으면 60분 차단
  • IP는 저장하지 않고 HMAC으로 "망 태그"만

07보안 모델

경계장치
브라우저 → 서버기본 바인드 127.0.0.1. 모든 요청에 isLoopback: 원격 주소, Host, Origin 셋 다 루프백이어야 함. 아니면 403 / WS 4003
메시지 권한handleClientMessage 맨 앞 게이트 하나. 새 메시지 타입은 기본 privileged
PC ⇄ PCX25519 + AES-256-GCM, TOFU 키 고정, 재전송 방지. 피어 데이터로 실행·쓰기 금지 (예외: 검증된 공유 레이아웃만)
정보 노출공개 오피스엔 quietView(작업 대상·이유 제거), 팀엔 redactView. 트랜스크립트·사용량·경로는 로컬 전용
업데이트github.com URL만, 크기 상한, SHA-256 필수, tar 경로 탐색·링크 거부
백신 오탐 대응PowerShell·VBS 금지. 트레이·런처는 C# 실행 파일 (레지스트리·자식 프로세스·네트워크 없음)

09설치 파일이 만들어지기까지

esbuild는 이 과정의 한 단계만 맡는다. JS 파일 하나(dist/cli.js)를 만들 뿐, 실행 파일(exe)로 만들지는 않는다. Node를 exe 하나로 합치는 도구(pkg, Node SEA)도 쓰지 않는다. 대신 공식 node.exe를 설치 폴더에 그대로 넣고, 작은 C# 런처가 그 Node로 cli.js를 실행한다.

1 · ESBUILD

서버 번들

esbuild.js: server/src/cli.ts와 Fastify까지 묶어 dist/cli.js 한 파일로. node_modules 없이 실행됨

2 · VITE

화면 빌드

SPA를 dist/webview/로, 스프라이트는 dist/assets/로

3 · NODE

런타임 확보

fetch-node.mjs: node-version.txt(v22.23.3)에 적힌 공식 바이너리를 받아 SHA-256 검증

4 · CSC

런처 · 트레이

Windows 내장 csc.exe로 C# 컴파일: PixelOffice.exe, PixelOfficeTray.exe

5 · INNO

설치 파일

ISCC.exe windows.iss → PixelOffice-<ver>-Windows.exe

6 · RELEASE

GitHub Release

태그 v<ver> push → .exe, .pkg, 무음 업데이트용 app.tgz 업로드

1~2단계는 npm run package가 한다. 3~6단계는 .github/workflows/package.yml이 Windows와 macOS 러너에서 돌린다.

설치 후 폴더 (Windows)

  • 제거 시 앱 종료, 폴더·바로가기 정리 (사용자 데이터는 묻고 삭제)

macOS (.pkg)

  • macos.sh: arm64용과 x64용 Node를 lipo -create로 하나로 합쳐 Pixel Office.app에 넣음
  • 런처는 셸 스크립트, 트레이는 osascript JXA
  • pkgbuild로 .pkg, 로그인 시 시작은 LaunchAgent com.pixeloffice.agent

실행 흐름

PixelOffice.exe  ─▶  node.exe app\cli.js --open
                      └▶ Fastify가 127.0.0.1:47801 에서 대기
                      └▶ PixelOfficeTray.exe 띄움 (트레이 아이콘)
                      └▶ 설치된 PWA 창 또는 브라우저가 열려 /ws 로 접속

왜 이 구조인가

  • 관리자 권한 없는 무음 업데이트: 앱 본체가 dist/ 뿐이라 dist/만 tgz로 받아 ~/.pixel-office/app/<ver>/에 풀면 업데이트 끝. 바뀌지 않는 node.exe와 C# exe가 바뀔 때만 설치 파일 릴리스가 필요
  • 백신 오탐 회피: 예전 v1.0.0의 PowerShell 헬퍼는 Kaspersky가 악성으로 잡았다. 그래서 런처·트레이는 레지스트리·네트워크·자식 프로세스 없는 단순한 C# exe로 만듦

CI가 실제로 검증하는 것

  • Windows: 무음 설치 → URL 스킴 키 확인 → 서버 기동 → /VERYSILENT 제거 → 폴더·프로세스·키·바로가기 정리 확인 (데이터는 남음)
  • macOS: sudo installer → 에이전트·서버 기동 → 재설치 → 제거 → 앱·plist·프로세스 정리 확인
  • lipo -archs, codesign --verify, 트레이 smoke 테스트

설치 파일 없이 로컬에서 실행

npm install
npm run build                   # asyncapi 생성 → 타입 체크 → lint → esbuild → vite
node dist/cli.js --port 47801   # 그다음 http://localhost:47801

10설계 원칙 정리

  • 의존성 최소화: 서버 런타임 의존성은 Fastify 계열 4개뿐, 웹뷰는 React 2개. UDP·파일 감시·암호·차트·구문 강조·i18n은 표준 라이브러리나 직접 구현.
  • 스펙 주도 프로토콜: AsyncAPI → 코드 생성 → CI 드리프트 검사.
  • 로컬 우선: 클라우드 백엔드 없음. 각 PC가 자기 서버. 릴레이는 선택적이고 최소한만 나른다.
  • React는 크롬만: 게임 루프는 명령형 상태 + Canvas, 필요할 때만 렌더.
  • 순수 함수 분리: 판단 로직(hub.ts, editorActions.ts, *Model.ts, 게임 로직)은 순수 함수로 빼서 Vitest로 검증.
