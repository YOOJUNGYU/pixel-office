# 내 에이전트 세션 전문 패널 — 설계

작성일: 2026-11-03

## 의도

오피스에서 내 에이전트 캐릭터를 클릭하면, 그 세션이 지금까지 무엇을 했는지 **전부**(요청·답변·도구 호출·도구 결과)를 화면 좌측 패널에서 읽고, 에이전트가 일하는 대로 **실시간으로** 따라 본다. 터미널을 찾아가지 않고 오피스 화면에서 바로 확인하는 것이 목적이다.

## 목표

1. 이 PC의 에이전트 캐릭터(MAIN / SUB / SHELL) 클릭 → 화면 좌측에 전문 패널이 열린다. 대기실에서 아바타에 합쳐진 에이전트는 내 아바타 클릭 → 옆에 뜨는 목록에서 고른다. (사용자 결정)
2. 내용 = 그 세션 transcript 의 **모든 것**: 사용자 프롬프트, 에이전트 텍스트 답변, 도구 호출(도구 이름 + 입력 전체), 도구 결과(파일 내용·명령 출력 전체, 오류 표시). (사용자 결정)
3. 패널을 연 동안 새 줄이 생기면 **실시간으로 아래에 붙는다**. (사용자 결정)
4. Claude 와 Codex 둘 다.

## 반목표 / 절대 안 되는 것

- **다른 PC 의 에이전트 전문은 절대 보이지 않는다.** (사용자 결정) 남의 에이전트를 클릭하면 지금처럼 그 PC 선택만 한다.
- 전문은 **어떤 경로로도 피어에게 나가지 않는다** — `AgentView`/`PeerPacket`/presence/office snapshot 에 전문·경로·제목 어느 것도 넣지 않는다 (`SessionState.local` 과 같은 LOCAL ONLY 원칙). 이것이 깨지면 기능이 동작해도 실패다.
- 전문에서 무엇을 실행하거나 쓰지 않는다 (읽기·표시만).
- 검색·내보내기·복사 버튼·전문 편집, 세션 목록 탐색(지금 오피스에 없는 과거 세션 열기)은 이번 범위 밖.
- NetBird/원격 접속은 별도 작업 (보류).

## 제약 (기존 프로젝트 규칙)

- 프로토콜은 `core/asyncapi.yaml` 에 추가 → `npm run asyncapi:generate`. 새 메시지는 모두 `additionalProperties: false`, 새 client 메시지는 기본 privileged (`handleClientMessage` 의 게이트 그대로 — 보기 전용 ctx 는 거부).
- 런타임 의존성 추가 금지. 파일 읽기는 Node stdlib.
- 상수는 `server/src/constants.ts` / `webview-ui/src/constants.ts`, 색은 `constants.ts`, 문자열은 `i18n.ts` (ko/en).
- 픽셀 스타일(`borderRadius: 0`, `2px solid`, 하드 섀도), 폰트 Pretendard, 테마 변수(`index.css`) — 다크/라이트 둘 다.
- 캔버스 상태가 바뀌는 곳은 `requestRender` 규칙을 지킨다 (패널 자체는 DOM 이라 캔버스와 무관하지만 선택 아웃라인 등은 해당).

## 동작

### 누가 열 수 있나 (내 것 판정)

- 웹뷰: 클릭한 캐릭터의 에이전트가 `officeSnapshot.agents[].peer.id === selfPeerId` 일 때만 패널을 연다. 아니면 기존 동작(PC 선택).
- 서버: 요청받은 id 를 **이 PC 의 `Scanner` 안에서만** 찾는다. 피어 데이터는 조회 대상이 아니므로 남의 id 가 와도 찾을 것이 없다 → `transcriptError {notFound}`. 서버 쪽 판정이 진짜 방어선이고, 웹뷰 판정은 UX 용이다.
- 응답은 **요청한 소켓에만** 보낸다 (브로드캐스트 금지).

### 대기실의 내 에이전트 (아바타에 합쳐진 것)

대기실의 에이전트는 캐릭터 없이 내 아바타에 합쳐져 보인다 (턴 종료, 질문·승인 대기, 위임 중 — 가장 보고 싶은 순간들).

- **내 아바타를 클릭하면 아바타 바로 옆(우측, 화면 밖으로 나가면 좌측)에 대기실에 있는 내 에이전트 목록이 뜬다. 목록에서 하나를 클릭하면 전문 패널이 열린다.** (사용자 결정)
- 목록 항목: 얼굴 썸네일, MAIN/SUB 배지 + `tagText`, provider 배지, 기다리는 중이면 빨간 ! — `RoomTip` 의 카드 모양 재사용. (내 판단)
- 한 개뿐이어도 목록을 띄운다 (바로 열지 않음). 대기실에 내 에이전트가 없으면 목록은 뜨지 않고 지금 동작만. (내 판단)
- 내 아바타 클릭의 기존 동작(내 PC 선택 아웃라인)은 그대로 하고 목록을 함께 띄운다. 같은 아바타 다시 클릭·빈 바닥 클릭·Esc → 목록 닫힘. 목록은 아바타를 따라 움직인다(아바타가 걸으면 위치 갱신). (내 판단)
- 남의 아바타 클릭은 지금 그대로 (목록 없음).
- 열린 패널의 에이전트가 대기실로 가서 아바타에 합쳐져도 패널은 열린 채 실시간으로 계속 이어진다. 그때는 아웃라인할 캐릭터가 없으므로 아웃라인은 생략.

### 어떤 파일을 보여 주나

- MAIN: 그 세션의 transcript 파일 (Claude `projects/<proj>/<id>.jsonl`, Codex rollout 파일).
- SUB: 서브에이전트 자신의 transcript (`<parent>/subagents/agent-*.jsonl`).
- SHELL: 자기 transcript 가 없으므로 **부모 세션의 전문**을 연다. (내 판단)
- 파일 경로는 서버가 `Scanner` 의 `Tracked` 에서 찾는다 (id → file). 웹뷰는 경로를 모르며 받지도 않는다.
- 패널을 연 뒤 세션이 오피스에서 사라져도(TTL, 종료) 패널은 열린 채 마지막 내용을 유지한다. 파일이 사라지면 끝에 "세션이 끝났습니다" 한 줄. (내 판단)

### 표시 내용 (정규화)

서버가 transcript 줄을 공통 항목으로 바꿔 보낸다 (Claude/Codex 형식 차이는 서버에서 흡수):

| kind        | 내용                                                                                    |
| ----------- | --------------------------------------------------------------------------------------- |
| `user`      | 사용자가 보낸 프롬프트 텍스트                                                           |
| `assistant` | 에이전트 텍스트 답변                                                                    |
| `thinking`  | 사고 블록 (있을 때만, 기본 접힘)                                                        |
| `tool`      | 도구 이름 + 입력 전체 (JSON 또는 명령 문자열)                                           |
| `result`    | 도구 결과 전체 (텍스트), `error` 여부; 짝이 되는 `tool` 과 연결 (tool_use_id / call_id) |
| `meta`      | 세션 시작·모드 변경·압축(compaction)·훅 출력 등 사람이 읽을 만한 시스템 줄 (짧게)       |

- 각 항목: `ts`(있으면), `kind`, `text`, 필요 시 `tool`, `error`.
- 렌더링용 잡음 줄(`api-request`, `last-prompt`, `atis-latch`, `deferred_tools_record`, 빈 첨부 등)은 버린다. 어떤 줄을 `meta` 로 남기고 무엇을 버릴지는 빌더 판단이되, **사람이 쓴 입력과 에이전트 출력·도구 입출력은 하나도 버리지 않는다.**
- 이미지 블록 등 텍스트가 아닌 결과는 `[이미지]` 같은 자리표시.
- Codex: `response_item` 의 message / reasoning / function_call / function_call_output / local_shell_call 등, `event_msg` 의 user_message 등을 같은 kind 로 매핑.

### 크기 (큰 transcript)

실제 파일이 10 MB 이상인 경우가 흔하다 (이 PC 에 17 MB 있음).

- 처음 열면 **파일 끝에서부터 일정량**(예: 마지막 ~512 KB 또는 ~N 항목)을 보낸다 + "이전 내용 있음" 표시.
- 패널 맨 위로 스크롤하면 그 앞 구간을 더 요청한다 (바이트 오프셋 기준 페이지). 끝까지 가면 "세션 시작".
- 항목 하나의 `text` 는 서버에서 상한(예: 200 KB)을 두고 넘으면 잘라 "… (N KB 생략)" 를 붙인다. 화면에서는 긴 `result`/`tool` 을 기본 몇 줄만 보이게 접고 [펼치기]. (전부 보이는 것이 목표이므로 상한은 넉넉하게, 브라우저가 멈추지 않는 선에서)
- 수치는 상수로 두고 빌더가 실제 파일로 정한다.

### 실시간

- 패널이 열려 있는 동안 서버가 그 파일의 끝을 따라 읽어(기존 scanner poll 주기 수준, ~1 s) 새 항목을 `transcriptAppend` 로 보낸다.
- 사용자가 맨 아래에 있으면 자동으로 따라 내려가고, 위로 올려 읽는 중이면 붙이기만 하고 스크롤은 그대로 + "새 내용 ↓" 버튼. (내 판단)
- 패널을 닫거나 다른 에이전트로 바꾸거나 소켓이 끊기면 서버는 그 구독을 멈춘다. 한 소켓당 구독 1개.
- 파일이 줄어들면(잘림/재작성) 처음부터 다시 보낸다.

### 화면

- 좌측 세로 패널: 상단 바에 MAIN/SUB/SHELL 배지, `#n`, provider 배지(Claude/Codex 색), 세션 제목(`Scanner.info` 의 title), 폴더, [×]. 그 아래 스크롤되는 항목 목록.
- 항목 모양: user = 오른쪽/강조 말풍선 느낌, assistant = 본문, tool = 도구명 칩 + 코드 블록(고정폭), result = 코드 블록(오류면 빨간 테두리), thinking/meta = 흐린 작은 글씨. 마크다운 렌더링은 하지 않고 줄바꿈 보존 텍스트. (내 판단: 의존성 없이 안전)
- 닫기: [×], Esc(텍스트 입력에 포커스가 없을 때, 기존 Esc 단계 처리와 충돌하지 않게), 같은 캐릭터 다시 클릭. 빈 바닥 클릭은 선택만 해제하고 패널은 유지할지 닫을지는 빌더 판단 (권장: 유지).
- 패널이 열려 있는 동안 해당 캐릭터는 기존 선택 아웃라인.
- 위치: 좌측 상단 컨트롤(테마·줌·이름표 토글)과 좌측 하단 툴바를 가리지 않도록 그 사이 높이를 쓰거나, 패널이 위에 덮되 컨트롤을 패널 오른쪽으로 비켜 둔다 — 빌더 판단. 모바일(좁은 화면)에서는 화면 폭 대부분.
- 편집 모드·투어 중에는 열리지 않는다(열려 있으면 닫힘).

## 프로토콜 (초안 — 이름·필드는 빌더가 다듬어도 됨)

client → server (privileged):

- `openTranscript {id}` — 구독 시작 (이전 구독 대체).
- `loadTranscriptBefore {id, before}` — `before` 오프셋 앞 구간.
- `closeTranscript {}`.

server → 요청 소켓만:

- `transcriptLoaded {id, info {kind, provider, num, title, folder}, entries[], start, more}` — `start` = 이 묶음 첫 바이트 오프셋, `more` = 그 앞이 남았는지.
- `transcriptAppend {id, entries[]}`.
- `transcriptEarlier {id, entries[], start, more}`.
- `transcriptError {id, reason: 'notFound' | 'unreadable' | 'ended'}`.

`title`/`folder` 는 이 PC 화면에만 가는 로컬 정보다 (알림과 같은 출처).

## 테스트

- 서버: Claude·Codex 샘플 줄 → 정규화 항목 (모든 kind, 짝 연결, 잡음 버림, 긴 text 자르기).
- 서버: 페이지 경계가 줄 중간이어도 항목이 깨지지 않음 / `more` 정확.
- 서버: 남의(스캐너에 없는) id → `notFound`; 응답이 요청 소켓에만 감; 보기 전용 ctx 거부.
- 서버: 패킷 회귀 — `views(true)`/PeerPacket 에 전문 관련 필드가 없음 (scanner.test 의 기존 LOCAL ONLY 검사 확장).
- 웹뷰: 내 것/남의 것 클릭 분기, 자동 스크롤 규칙(순수 함수로 분리).

## 구현 메모 (검토에서 확인, 내 판단)

- `OfficeCanvas` 의 `onClick` 은 지금 `App` 에서 연결돼 있지 않다 → 새로 연결하고 `Character.peerId` + 에이전트 키로 판정한다.
- "에이전트 선택 후 의자 클릭 = 자리 이동"(`performTap` 옛 코드) 경로와 패널 열기를 섞지 않는다.
- 좁은 화면(터치)의 "첫 탭 = 선택, 같은 캐릭터 두 번째 탭 = 열기" 규칙은 그대로 둔다.
- 스캐너는 파일 끝부분(`TAIL_BYTES`)만 읽고, 세션이 떠나면 파일을 잊는다 → 전문 구독은 스캐너의 `Tracked` 를 재사용하지 않고 자기 파일 경로·오프셋을 따로 가진다. 열 때 id → 파일 경로만 스캐너에서 얻는다.
- SHELL 의 부모는 `${s.id}/sh/…` 의 `s.id` — 서브에이전트일 수도 있다. 그 세션의 전문을 연다.
- Codex 는 사용자 프롬프트를 `event_msg user_message` 와 `response_item` (role user) 두 번 쓴다 → 정규화에서 하나로 합친다.

## 빌더에게 맡기는 것

- 정규화 코드 위치(새 `server/src/lan/transcript.ts` 권장)와 파일 추적 방식(scanner 의 poll 에 얹을지 별도 타이머일지).
- 페이지 크기·항목 상한·접힘 줄 수 상수 값.
- 패널 컴포넌트 구조, 정확한 배치, 항목 디자인 세부.
- `meta` 로 남길 시스템 줄의 범위.
