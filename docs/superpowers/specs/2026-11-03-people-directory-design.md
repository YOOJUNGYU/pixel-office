# 접속자 패널 3영역 (공개 / 팀 / 개인용) — 설계

작성일: 2026-11-03

## 의도

지금 LAN 에 누가 어디에 있는지 한눈에 본다. 우측 접속자 패널을 **공개 / 팀 / 개인용** 세 영역으로 나눠 각 영역에 지금 접속 중인 사람(아바타 얼굴 + 이름)을 보여 준다. 개인용 모드인 사람도 보이게 한다 (지금은 개인용 모드 PC 가 LAN 에서 완전히 보이지 않는다).

## 목표 (사용자 결정)

1. 상단 오피스 탭(🌐 공개 / 🔒 팀 / 🏠 개인용)에서 `· N명` 인원 표시를 **모두 없앤다**.
2. 우측 접속자 패널 = 세 영역, 위에서부터 **공개 오피스 → 팀 → 개인용**. 각 영역: 제목 + 인원 수, 그 아래 사람 목록(얼굴 썸네일 + `peerLabel` = `account (nickname)`), 나는 내 영역 맨 위.
3. **어떤 모드의 PC 에서도(공개·팀·개인용) 세 영역이 모두 보인다.**
4. **팀 영역 = 내가 가입한 팀만.** 팀마다 하위 제목(팀 이름) + 그 팀의 지금 접속 멤버. 가입하지 않은 팀의 멤버는 보이지 않는다. 팀 멤버십은 지금처럼 팀 안에서만 알 수 있다. **가입한 팀이 하나도 없으면 팀 영역 자체를 보여 주지 않는다.** (사용자 결정)
5. **개인용 영역 = 지금 개인용 모드인 사람, 이름까지.** (사용자 결정: 이름까지 알림)

## 반목표 / 절대 안 되는 것

- 개인용 PC 의 **에이전트 활동·채팅·아바타 위치는 여전히 PC 밖으로 나가지 않는다.** 나가는 것은 이름 카드(계정·닉네임·외형)뿐.
- 팀 이름·팀 멤버십·팀 키가 팀 밖으로 새지 않는다. LAN 평문에 실리는 것은 기존 hello 와 같은 수준(`id`, `pk`)뿐.
- 다른 영역의 사람은 내 오피스 화면(아바타·에이전트·채팅 말풍선·알림)에 나타나지 않는다. 목록에만.
- 1.0.24 이하 PC 가 개인용/팀 PC 를 공개 오피스 사람으로 잘못 세지 않는다.
- 피어 데이터로 무엇을 실행하거나 쓰지 않는다 (표시만, 기존 원칙).

## 제약

- UDP 47800 하나, 데이터그램 ≤ `MAX_DATAGRAM_BYTES` (1200), 새 포트 없음, 새 런타임 의존성 없음.
- 기존 v2 프로토콜 규칙 재사용: X25519 페어 키(`pairKey`), TOFU 핀(`known-peers.json`), AES-256-GCM `seal/open`, `parseWire` 엄격 파싱(모르는 `t` 는 null — 구버전은 새 타입을 조용히 버린다).
- 프로토콜(asyncapi) 규칙, 상수·색·i18n·픽셀 스타일 규칙은 프로젝트 CLAUDE.md 그대로.

## 동작

### LAN 신호 (새 v2 타입 2개)

1. **`watch {v:2, t:'watch', id, pk}`** — 평문 브로드캐스트. **공개 오피스에 있지 않은 모든 PC**(개인용 모드, 팀 가입 중)가 전송 주기마다 보낸다. 뜻: "나는 공개 오피스엔 없지만 목록을 보고 싶다". 개인용인지 팀인지는 싣지 않는다 (팀 사용 여부가 평문으로 새지 않게). 받는 쪽은 hello 와 같은 TOFU 핀 검사를 한다.
2. **`card {v:2, t:'card', from, to, n, c}`** — 페어 키로 봉인한 유니캐스트, AAD `card|from|to`. **개인용 모드 PC 만** 보낸다. 받는 곳: hello 로 알게 된 공개 PC + watch 로 알게 된 PC 전부. 평문 = `{seq, peer: {id, account, nickname, nickSince?, palette, hueShift, pet?, tagColors?}}` (기존 `PeerInfo` 검증 재사용, 에이전트·채팅·아바타 없음). seq 재전송 방지는 기존 채널별 방식.

그리고 **공개 PC 의 기존 `pub` presence 를 watch 한 PC 에게도 보낸다** (지금 hello 한 PC 에게 보내는 것과 같은 봉인·같은 내용). 공개 오피스 presence 는 원래 LAN 의 누구든 hello 만 하면 받는 정보라 공개 범위가 넓어지지 않는다. watch 하는 PC 는 받은 pub 에서 **사람 정보만** 쓰고 에이전트·아바타·채팅은 쓰지 않는다.

팀 영역: 팀 presence 는 지금도 가입한 팀이면 (개인용 모드에서도) 복호화된다. 그것으로 채운다. 추가 신호 없음.

나: 공개(팀 없음·개인용 아님) → 공개 영역; 팀 가입 중 → 가입한 각 팀 영역(그 팀을 보고 있든 아니든); 개인용 → 개인용 영역. (내 판단: 팀 가입 중에는 공개 오피스가 열려 있지 않다는 기존 규칙(`isViewOpen`)을 그대로 따른다)

수명: 모든 항목은 기존 `PEER_TTL_MS` 로 만료.

### 구버전 호환

- ≤ 1.0.24 공개 PC: `watch`/`card` 를 버리고, watch PC 에게 pub 을 보내지 않는다 → 그 PC 는 새 PC 의 공개 영역에서 빠질 수 있다 (이미 hello 를 들은 경우에도 이름이 없으므로 표시 안 함). 감수.
- ≤ 1.0.24 PC 는 개인용/팀 PC 를 보지 못한다 (지금과 같음).
- 새 공개 PC 는 hello 한 PC 만 공개 오피스 사람으로 센다 (watch PC 는 절대 공개 영역·공개 오피스 화면에 안 들어감).

### 서버 → 화면

- 새 서버 메시지 **`peopleDirectory {public: Person[], teams: [{tag, name, people: Person[]}], personal: Person[]}`** — 기존 `officeSnapshot` 과 같은 주기(1 s)로 모든 UI 소켓에. `Person` = `{peerId, account, nickname, nickSince?, palette, hueShift, pet?, tagColors?, self}` (기존 `OfficePersonMessage` 에서 chat·avatar 를 뺀 것). (내 판단: 스냅샷을 키우지 않고 별도 메시지)
- 상단 탭 인원 표시 제거. `officeSnapshot.online` 은 프로토콜 호환을 위해 남겨도 화면에서 쓰지 않는다 (빌더 판단: 아무도 안 쓰면 제거해도 됨).
- 닉네임 동점 처리·이름 표기(`peerLabel`, `nicknames.ts`)는 영역마다 같은 규칙.

### 우측 패널 화면

- 제목 줄은 지금처럼 접기/펼치기. 그 아래 세 영역. 영역 제목: `공개 오피스 · N`, `팀 · N` (가입한 팀이 없으면 영역 숨김), 팀마다 `🔒 <팀 이름> · N`, `개인용 · N`. 사람이 0 인 영역은 제목만 + "없음" (공개·개인용), 팀 영역은 가입 팀이 있을 때만.
- **내가 지금 보고 있는 오피스의 영역**은 지금 패널의 행 기능(에이전트 수/상태 표시, 클릭 시 그 PC 선택·하이라이트, 채팅 표시 등)을 그대로 가진다. 다른 영역의 행은 얼굴 + 이름만 (클릭해도 아무것도 안 함). (내 판단)
- 높이: 지금처럼 우측 상단 스택의 남은 높이, 넘치면 스크롤.

## 테스트

- PeerNet 두·세 인스턴스(루프백 포트, 기존 테스트 패턴):
  - 개인용 A + 공개 B: B 의 personal 에 A(이름), A 의 public 에 B(이름).
  - 개인용 A + 개인용 C: 서로 personal 에 보임.
  - 팀 T + 개인용 A: T 의 personal 에 A, A 의 팀 영역에는 T 없음(같은 팀이 아니면).
  - 팀 T + 공개 B: T 의 public 에 B; B 의 public 에 T 없음.
  - 키가 바뀐 watch/card 거부(핀), 다른 키로 봉인된 card 거부.
  - 구형 파서(현재 `parseWire` 이전 동작 흉내)는 watch/card 를 null 로 버림.
  - watch PC 는 공개 PC 의 `peers(PUBLIC_VIEW)`·`people`·스냅샷에 들어가지 않음.
  - card 에 에이전트·채팅·아바타 필드가 없음 (직렬화 검사).
- 데이터그램 ≤ 1200 B.
- 웹뷰: 영역 모델 순수 함수(정렬: 나 먼저, 팀 이름 순), 탭에서 인원 표시가 사라짐.

## 검토에서 정한 것 (내 판단)

1. **팀에 가입한 채 개인용 모드인 PC = 개인용이 이긴다.** 개인용 영역에만 나오고 card 를 보낸다. 지금처럼 팀 presence 는 보내지 않는다 (팀 presence 를 듣기만 하는 기존 동작 유지 → 그 PC 의 팀 영역은 보이지만 그 PC 자신은 팀 영역에 없다). 그 PC 가 어느 팀 소속인지는 어떤 신호에도 실리지 않는다. 구현: PeerNet 의 "공개 오피스에 있음" = `!offline && offices().length === 0`, "팀 presence 송신" = `!offline && offices().length > 0`.
2. **card 의 송신자 pk 는 watch 에서만 얻는다.** 받는 PC 는 별도 `watchers` 맵(최대 `MAX_HELLO_PEERS`, `PEER_TTL_MS` 만료, 가득 차면 새 항목 무시 — hello 와 같은 규칙)에 `{pk, address, port, at}` 를 보관한다. 그 맵에 없는(또는 만료된) 송신자의 card 는 버린다 (버퍼링 없음: watch 가 매 주기 오므로 다음 주기에 맞춰짐). TOFU 핀은 hello 와 같은 `pins` 를 쓴다 (같은 id 는 hello 든 watch 든 같은 키여야 함). watchers 는 공개 인원·`peers()`·`hellos` 와 절대 섞이지 않는다.
3. **숨기기 설정은 이번에 만들지 않는다.** 사용자가 "이름까지 알림"을 골랐고 숨기기는 요청하지 않음. 필요하면 나중에 `hideWork` 와 같은 프로필 토글로 추가.
4. **팀 이름을 아직 모르는 팀**의 하위 제목은 오피스 탭이 그 팀에 쓰는 표시와 같은 대체 문구를 쓴다. 두 팀에 모두 있는 멤버는 두 팀 목록에 모두 나온다.
5. **모드를 바꾼 직후의 중복**: 디렉터리는 공개·개인용 사이에서 `peerId` 로 중복을 제거하고, 가장 최근에 들은 쪽이 이긴다. 팀 목록끼리는 중복 허용(4번).

## 빌더에게 맡기는 것

- PeerNet 안의 자료구조(watchers/cards 맵) 이름과 위치.
- `peopleDirectory` 를 `LanService` 에서 만드는 함수 이름.
- 패널 컴포넌트 분할, 영역 제목 문구(i18n ko/en), 접힘 상태 저장 여부.
