# 인터넷 공개 오피스 (Cloudflare 중계) — 설계

작성일: 2026-11-06

## 의도

지금 공개 오피스는 같은 망(UDP 브로드캐스트)에서만 보인다. 집이든 회사든 **어느 망에서든** 설치한 사람이면 같은 공개 오피스에 들어와 서로의 에이전트·아바타·채팅·공유 레이아웃을 보게 한다. 회사 보안과 Mac/Windows 혼용 때문에 **Pixel Office 외에 아무것도 설치하지 않는다** (VPN·ZeroTier·Tailscale 제외). 운영 비용은 0 — **Cloudflare 무료 한도 안에서만** 동작한다.

## 목표 (사용자 결정)

1. **공개 오피스 = 인터넷.** 설치한 누구든, 어느 망에서든 같은 공개 오피스에 들어온다. (사용자 결정, 2026-11-06)
2. **팀 오피스 = 지금처럼 같은 망 전용.** 바뀌는 것 없음. 개인용도 그대로.
   2a. **기존 사용자도 업데이트되면 자동으로 인터넷 공개 오피스에 연결.** 켜고 끄는 설정·첫 실행 안내 없음, 문서에만 안내. (사용자 결정, 2026-11-06)
3. **중계 = Cloudflare Workers + Durable Object.** 계정은 사용자 본인 소유(가입 완료). 배포는 사용자가 `wrangler login` 후 실행.
4. **접속자 수 상한**을 둔다 — 무료 한도를 넘지 않도록.
5. **메시지 양을 최소화·효율화**한다 (무료 한도의 핵심 지표가 DO 가 받는 메시지 수).
6. **일일 메시지 예산**을 센다. 한도에 닿으면 중계를 끊는다.
7. **만원·예산 소진·강퇴 어느 경우에도 공개 오피스에 머문다. 개인용으로 전환하지 않는다.** 중계만 끊기고 같은 망 UDP 는 계속 동작, 안내만 표시, 조건이 풀리면 자동 재접속. (사용자 결정 — 앞서 제안한 "개인용 전환"을 사용자가 철회)
8. **관리자 강퇴.** 사용자(관리자)가 특정 사람을 공개 오피스 중계에서 내보낼 수 있다.

## 반목표 / 절대 안 되는 것

- 중계(Cloudflare)가 공개 오피스 내용을 **수동으로** 읽을 수 있게 되는 것. 지금의 pairwise 암호화(`pub`, X25519 + AES-GCM)를 그대로 쓴다. 중계가 보는 평문은 지금 LAN 평문과 같은 수준(`id`, `pk`, 받는 사람 id)뿐. (내 판단: 처음 보는 peer 의 pk 는 중계의 roster 로 받아 TOFU 로 고정하므로, **중계 운영자가 악의적으로** 가짜 pk 를 끼우면 첫 만남의 쌍은 읽을 수 있다. 운영자 = 사용자 본인이므로 감수, `ponytail:` 주석 + 문서 한 줄. 지문 비교 UI 는 필요해지면.)
- 참여 제한. **누구든** (설치한 사람, 또는 URL 로 WebSocket 만 여는 사람도) 들어와 공개 오피스 전원의 계정명·닉네임·에이전트 활동 요약·채팅을 볼 수 있다 — 사용자 결정("설치한 누구든"). 방어는 상한 + 강퇴뿐.
- 팀 키·팀 데이터·개인용 데이터가 인터넷으로 나가는 것. 팀/개인용 PC 는 중계에 **연결하지 않는다**.
- 무료 한도 초과로 Cloudflare 가 요청을 거부할 때까지 방치하는 것 — 그 전에 우리 쪽 예산으로 끊는다. (Free 플랜은 초과 과금이 없고 실패만 하지만, 그날 남은 시간 동안 전원이 끊긴 상태를 우리 안내 없이 맞게 된다.)
- PC 에 추가 프로그램 설치, 들어오는 포트 개방. 중계 연결은 나가는 WSS(443)만.
- 새 런타임 의존성 (서버). Node 22 내장 `WebSocket` 을 쓴다 (`scripts/package/node-version.txt` = v22.23.3).
- 피어/중계에서 온 데이터로 무엇을 실행하거나 쓰는 것 (기존 원칙: 표시만, 공유 레이아웃만 예외).
- 중계 끊김이 같은 망 동작을 망가뜨리는 것.

## 구조

```
PC A (공개) ─WSS─┐                                   ┌─ 같은 망 PC 끼리는 지금처럼 UDP 도
PC B (공개) ─WSS─┼─ Worker ── DO "hub" (1개, 전역) ──┤
PC C (공개) ─WSS─┘   /ws, /admin/*                   └─ 팀/개인용 PC 는 연결 안 함
```

### 중계 서버 (`relay/`, 새 디렉터리)

- `relay/` = Worker + DO 소스, `wrangler.toml`. 루트 workspaces 에 넣지 않는다 (루트 `npm install` 이 wrangler 를 받지 않게). wrangler 는 `relay/package.json` devDependency 또는 `npx wrangler@<고정 버전>` — 빌더 판단.
- 레이어: `relay/` 는 `core/` 에만 의존 가능 (닫기 코드·프레임 타입 공유). 라우팅·예산·차단 판단은 **순수 함수**(`relay/src/hub.ts` 등)로 빼서 루트 vitest 로 테스트. DO 클래스는 얇은 껍데기.
- **DO 는 이름 고정 1개** (`idFromName('hub')`): 전역 접속자 수·예산·차단 목록을 한 곳에서 센다.
- **WebSocket Hibernation API** (`state.acceptWebSocket`, `webSocketMessage`, `webSocketClose`) 사용. 소켓별 `{id, pk}` 는 `serializeAttachment` 에 둔다 (잠들어도 유지). 연결 유지 ping 은 `setWebSocketAutoResponse` — DO 를 깨우지 않고 메시지로 세지 않는다.

### 프레임 (중계 ↔ PC, JSON 텍스트)

PC → 중계:

- 접속: `GET /ws?id=<peerId>&pk=<base64 pk>&v=<앱 버전>` (WebSocket 업그레이드). 형식 검사(`isWireId`, pk 길이) 실패 → 거부.
- `{t: 'send', w: Wire[]}` — 한 번에 보낼 **기존 Wire 객체들의 배열** (`pub` 만 허용; `to` 로 라우팅). 즉 지금 UDP 로 보내는 `pub` 데이터그램(분할 presence part·레이아웃 part 포함)을 그대로 묶어 보낸다. 새 암호 형식 없음, 받는 쪽은 기존 `receive` 경로 그대로.

중계 → PC:

- `{t: 'roster', peers: [{id, pk}]}` — 접속 직후 1회, 지금 접속 중인 전원.
- `{t: 'join', id, pk}` / `{t: 'leave', id}` — 변화 시 전원에게.
- `{t: 'w', w: Wire}` 또는 같은 PC 앞으로 온 것 묶음 — 라우팅된 `pub`.
- 거부/종료는 WebSocket close code + reason JSON: `full`, `budget {retryAt}`, `kicked {until}`, `replaced`, `bad`. 코드 값은 `core/src/constants.ts` 에 (4000번대, 기존 4003/4010/4011 과 겹치지 않게).

PC 쪽에서 roster/join 으로 들어온 `{id, pk}` 는 **UDP hello 를 받은 것과 똑같이** `heard()` 로 처리한다 (TOFU 핀 검사 포함, `MAX_HELLO_PEERS` 포함). 중계 쪽 peer 는 `Heard` 에 "중계 경유" 표시를 단다.

### 같은 id 중복

같은 id 로 새 소켓이 오면 **pk 가 같을 때만** 옛 소켓을 `replaced` 로 닫고 새 것을 받는다 (네트워크 끊김 후 재접속). pk 가 다르면 새 것을 거부. (빌더 판단 여지: 증명 없는 id 이므로 같은 id+pk 를 흉내 내면 상대를 밀어낼 수는 있다 — 내용은 못 읽는다. 무료 취미 서비스로 감수. `ponytail:` 주석으로 상한 명시.)

## 메시지 최소화 (핵심)

DO 가 **받는** 메시지만 센다는 점을 이용한다. 원칙: 보내는 PC 당, 변화가 있을 때만, 한 프레임.

1. **변할 때만 보낸다.** UDP 는 지금처럼 1 초마다(공짜). 중계 쪽은 내 공개 presence 가 바뀔 때만 보낸다. "바뀜" = `getPacket(PUBLIC_VIEW)` 를 **`ageSec` 를 뺀** JSON 으로 비교. `ageSec` 는 받는 쪽이 이미 자기 시계로 늘린다(`aged`) — 매초 보낼 이유가 없다.
2. **생존 신호 없음.** 살아 있음은 중계의 roster/join/leave 가 알린다. 중계 경유 peer 는 PEER_TTL_MS(5 s) 만료 대상이 아니라 **leave 를 받을 때까지 live**. 중계 연결이 끊기면 중계 경유 peer 는 전부 즉시 정리 (UDP 로도 들리는 peer 는 UDP 쪽 TTL 로 계속 산다).
3. **PC 당 최대 1 초에 1 프레임.** 아바타 걷기(최대 5/s)·채팅 등 연속 변화는 1 초 창으로 합친다 (`RELAY_MIN_SEND_MS`).
4. **한 프레임에 받는 사람 전원.** `send.w` 에 받는 사람별 sealed `pub` 를 모두 담는다 → 접속자 N 명이어도 보내는 PC 당 수신 1 건. 크기 상한: 프레임 ≤ `RELAY_MAX_FRAME_BYTES` (Cloudflare WS 메시지 상한보다 충분히 작게, 1 MiB 미만). 넘으면 큰 presence 부터 `fitPacket` 처럼 줄이거나 다음 틱으로 미룬다 — 빌더 판단.
5. **새 사람이 오면 그 사람에게만.** `join` 을 받은 각 PC 는 다음 송신 때 그 사람 앞 `pub` 을 포함 (변화 없어도). 접속자 N 이면 신규 1 명당 수신 N−1 건. (내 판단) "새 사람" = 중계가 받은 **모든 새 소켓** (같은 id 교체 포함 — 중계는 교체 때도 `leave`+`join` 을 보낸다), 그리고 UDP 로 들리다가 TTL 이 지나 중계로만 닿게 된 peer. 내 중계 연결이 새로 열린 경우엔 roster 전원이 "새 사람". peer 별 "전체 송신 필요" 플래그로 관리.
6. **UDP 로 들리는 peer 는 중계로 보내지 않는다.** 같은 망 peer (UDP hello 가 TTL 안) 는 UDP 로만. 중계 프레임에는 중계로만 닿는 peer 만.
7. **조용하면 DO 가 잠든다.** 1–2 와 auto-response ping 덕에 아무도 안 움직이면 DO 가 hibernate → duration 거의 0.
8. **공유 레이아웃도 중계로 주고받는다** — 인터넷 접속자도 편집·저장 가능, 마지막 저장이 이김 (사용자 결정, 2026-11-06). push 로직(`layoutToPush`, `LAYOUT_PUSH_MS`) 그대로. 레이아웃 part 는 presence 와 같은 프레임에 싣되 프레임 상한(4번)을 넘으면 여러 프레임으로 나눈다 (최대 512 part × 420 B ≈ 215 KB/받는 사람; 기본 레이아웃은 deflate 후 ≈ 6 KB). 저장은 드물어서 예산 영향은 무시할 수준.
9. **송신 속도 제한 (중계 쪽, 내 판단).** 레포가 공개라 누구든 WS 를 직접 열어 프레임을 쏟아 예산을 태울 수 있다. 소켓당 `RELAY_MAX_FRAMES_PER_MIN` (예: 120 — 정상 PC 는 최대 60 + 신규 peer·레이아웃 분할 여유) 을 넘으면 그 id 를 `kicked` 로 닫고 `RELAY_ABUSE_BAN_MIN` (예: 60 분) 자동 차단. 받은 순간 이미 과금되므로 피해 상한 = 한 소켓이 끊기기 전 1 분치.

예상: 사람이 바뀌는 건 대부분 에이전트 act 변화(수 초~수십 초 간격)와 걷기. 1 초 주기 대비 수신량 대략 1/5–1/10 (추정, 구현 후 측정해서 상한 값을 다시 정한다).

최악 계산: 상한 20 명이 **24 시간 내내 매초** 바뀌어도 20 × 86,400 = 1,728,000 < 예산 1,800,000. 즉 상한 20 이면 정상 클라이언트만으로는 예산을 넘을 수 없다. 남는 위험은 비정상 클라이언트 → 9번.

9a. **중계로는 작업 상세를 보내지 않는다** (사용자 결정, 2026-11-06). 인터넷으로 받은 다른 사람 에이전트는 **말풍선(작업 내용)만 안 보이고 동작은 그대로** — 방 이동(코딩실/자료실/서버실/대기실), 앉아서 타이핑, PC 화면, 서버실 LED, 확인 대기 ! 유지. 빠지는 것: target·reason·경과 시간·할 일 수·변경 줄 수·실패 표시 (→ 말풍선·호버 말풍선·효과 없음). 이로써 target 변화(파일마다 바뀜)·경과 시간이 송신을 일으키지 않는다. **같은 망(UDP)도 동일하게 적용** — 공개 오피스의 다른 사람 에이전트는 어디서 왔든 똑같이 보인다 (사용자 결정, 2026-11-06). **내 에이전트는 내 화면에서 상세·말풍선 그대로.** 팀 오피스는 범위 밖 (같은 망 전용, 변경 없음 — 내 판단). ≤ 1.0.41 PC 는 `quiet` 를 몰라 target 없는 활동 문구("읽는 중")를 말풍선으로 보일 수 있다 — 감수.

## 접속자 상한 · 예산 · 재접속

- **상한**: 동시 소켓 `RELAY_MAX_PEERS` (기본 20, `wrangler.toml` vars 로 바꿀 수 있게). 넘으면 업그레이드 직후 `full` 로 닫는다.
- **예산**: DO 가 받은 메시지 수(프레임 수 + 업그레이드 수)를 센다. 메모리 카운터 + `RELAY_BUDGET_FLUSH` 건마다 저장소에 기록 (DO 쓰기 한도 보호; 잠들기 직전 유실분 ≤ flush 간격 — `ponytail:` 주석). 날짜(UTC)가 바뀌면 0.
  - 예산 = 무료 환산 한도의 **90%** (`RELAY_DAILY_BUDGET`, 기본 1,800,000 메시지 상당 — 업그레이드 1 건 = 메시지 20 건으로 환산).
  - 닿으면 전원 `budget {retryAt: 다음 UTC 00:00}` 로 닫고, 그때까지 새 업그레이드도 거부.
- **PC 쪽 동작 (모든 거부 공통)**: 공개 오피스에 **그대로 머문다**. 중계만 끊긴 상태로 같은 망 UDP 는 정상. 재접속:
  - `full` → `RELAY_RETRY_FULL_MS` (예: 5 분) + 지터.
  - `budget` → `retryAt` 이후 + 지터 (전원이 9 시 정각에 몰리지 않게 0–10 분).
  - `kicked` → `until` 이후.
  - 네트워크 오류·서버 미응답 → 지수 백오프 (최소 5 초, 최대 5 분).
  - `replaced` → 재접속 안 함 (같은 PC 다른 인스턴스 — 실제로는 single-instance 라 거의 없음).
- **공개 오피스를 떠나면**(팀/개인용으로 전환) 중계 연결을 닫는다. 돌아오면 다시 연결.

## 관리자 강퇴

- 중계 Worker 비밀 값 `ADMIN_TOKEN` (`wrangler secret put ADMIN_TOKEN`). 레포·설치 파일에 절대 넣지 않는다.
- Worker 관리자 API (`Authorization: Bearer <token>`, 상수 시간 비교, 그 외 401):
  - `POST /admin/kick {id, hours?}` — 그 id 의 소켓을 `kicked {until}` 로 닫고 차단 목록에 등록 (기본 24 h, `RELAY_KICK_HOURS`). 저장소에 기록 (DO 가 잠들어도 유지).
  - `GET /admin/bans` / `DELETE /admin/bans/<id>` — 목록·해제. **앱 UI 없음, curl 로** (설치 안내 문서에 예시).
  - `GET /admin/stats` — 접속자 수, 오늘 사용 예산 (curl).
- **앱 안 [강퇴]** (중계는 이름을 모르므로 이름이 보이는 앱에서 누른다):
  - Settings 에 "관리자 토큰" 입력란. 저장 위치 = `config.json` `standalone.relayAdminToken` (로컬 서버만 보관, 웹뷰에는 "설정됨" 여부만 보낸다, 토큰 값은 다시 내려보내지 않는다).
  - 토큰이 설정된 PC 에서만 접속자 패널의 공개 오피스 행(나 제외)에 [강퇴] 버튼. 확인 창 후 `relayKick {peerId}` (privileged) → 로컬 서버가 Worker `POST /admin/kick` 호출 → 결과를 그 소켓에만 (`relayKickResult {ok, reason?}`, 토스트).
- **강퇴된 쪽**: 공개 오피스에 머문다. 중계만 끊기고 "관리자에 의해 인터넷 공개 오피스에서 퇴장 (~HH:MM 까지)" 안내.
- **한계 (문서화)**: 차단은 peer id 기준 — `profile.json` 을 지우면 새 id 로 피할 수 있다. IP 차단은 하지 않는다 (회사 NAT 뒤 전원이 같은 IP).

## 상태 표시

- 새 서버 메시지 `relayState {state, until?}` — `state ∈ off|connecting|connected|full|budget|kicked|error`. 핸드셰이크에 포함 + 바뀔 때마다 전원 소켓에. `asyncapi.yaml` 에 추가 (additionalProperties false).
- 웹뷰: 공개 오피스를 볼 때 접속자 패널 "공개 오피스" 제목 옆에 작은 상태 칩 (연결됨 = 🌐, 그 외 = 사유 툴팁/한 줄). 문구는 `i18n.ts` (ko/en). 개인용/팀 화면에서는 안 보임. 정확한 위치·모양은 빌더 판단 (기존 픽셀 스타일 규칙 준수).

## 서버 쪽 변경 범위

- `server/src/lan/relay.ts` (새): 중계 클라이언트. 연결·재접속·프레임 송수신·상태. 순수 부분(재시도 시각 계산, close reason 파싱, 변화 감지 키)은 테스트 가능한 함수로.
- `server/src/lan/peerNet.ts`: 두 번째 입구. 중계에서 온 roster/join → `heard()`, `w` → 기존 `receive()` 와 같은 처리(rinfo 대신 "중계" 표시), leave/끊김 → 중계 peer 정리. `sendNow()` 에서 중계로만 닿는 peer 앞 `pub` 은 UDP 대신 모아 두었다가 변화가 있거나 신규 peer 가 있을 때만 중계 프레임 1 개로. TTL 검사(`prune`, `peers`, `directory`)에서 중계 live peer 예외.
- `server/src/cli.ts`: `Relay` 생성·시작, 공개 오피스 여부에 따라 열고 닫기.
- 중계 URL: `server/src/constants.ts` `RELAY_URL` (배포 후 실제 workers.dev 주소로), 환경변수 `PIXEL_OFFICE_RELAY_URL` 로 덮어쓰기 (테스트, 빈 문자열 = 끔). `wss://` 만 허용 (테스트용 `ws://127.0.0.1|localhost` 예외 — updater 의 테스트 API 예외와 같은 방식).
- 프로토콜 상수(닫기 코드 등): `core/src/constants.ts`.

## 호환

- ≤ 1.0.41 PC 는 중계를 모른다 → 같은 망에서만 보인다 (지금과 같음). 새 PC 끼리는 같은 망이면 UDP + 중계 둘 다로 받지만 중계로는 보내지 않으므로(6번) 중복 없음; 혹시 겹쳐도 seq 재전송 방지(`fresh`)가 거른다.
- 팀/개인용 PC 가 공개 PC 를 듣는 watch/card 경로는 같은 망 전용 그대로 (인터넷 사람은 팀/개인용 PC 의 접속자 패널 "공개" 영역에 안 나온다 — 비목표).

## 테스트

- `relay/` 순수 함수: 라우팅(받는 사람 없는 `to` 버림, `pub` 외 거부), 상한, 예산 카운트·리셋·90%, 차단 만료, 같은 id 교체 규칙, 관리자 토큰 검사.
- `server/__tests__/lan/relay.test.ts`: 로컬 가짜 중계(Node `http` + 최소 WS 서버는 테스트 전용 — 새 런타임 의존성 아님; 어렵다면 Worker 를 `wrangler dev` 로 띄우는 수동 e2e 로 대체, 빌더 판단)로 두 PeerNet 이 UDP 없이 서로 보이는지, 변화 없을 때 프레임 0 건, 1 초 창 합치기, close 사유별 재접속 시각, 강퇴 후 공개 오피스 유지.
- `peerNet` 기존 테스트 전부 통과 (UDP 경로 불변).

## 나중에 (문제가 생기면) — 지금 만들지 않는다

사용자 결정 (2026-11-06): 알려진 공격자가 없으므로 남용 방어는 9번(소켓 속도 제한 + id 자동 차단)과 관리자 강퇴까지만. 최악의 경우도 "그날 중계 중단, 같은 망은 정상, 비용 0" 으로 한정된다. 공격이 실제로 생기면 아래 순서로 추가:

1. 속도 제한 위반 시 IP(`CF-Connecting-IP`) 자동 차단 — 회사 NAT 공유 IP 동료도 함께 막히는 부작용.
2. 관리자 수동 IP 차단 (`/admin/ban-ip`).
3. Cloudflare WAF 레이트 리밋 규칙 (무료 1 개, 커스텀 도메인 필요) — 재접속 폭주를 Worker 전에 차단.
4. Turnstile 로 사람 확인 후 서명된 접속권 발급 — id 대량 생성 봇 차단.
